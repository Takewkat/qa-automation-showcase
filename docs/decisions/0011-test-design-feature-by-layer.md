# 0011 Test design on two axes: feature by layer

Context: the author's API suites at Hublo were designed on a fixed grid per feature: `@happy-path` the acceptance of the behaviour, `@validation-error` the requests the contract refuses (missing or null field, empty payload, negative, zero), `@error-case` 401, 403 and 404 per resource, plus feature tags for the business dimension (local and shared network). The grid is read endpoint by endpoint, so a status the spec documents and no test exercises shows as an empty cell. The first cut of this suite was grouped by risk only; laid on the grid, 401 was covered on 3 of the 10 operations and neither update nor configuration had a validation test.

Decision: every `test()` carries two tags, its folder (`@tenancy`, `@offers`, `@workflow`, `@configuration`, `@listing`, `@history`) and exactly one layer (`@happy-path`, `@validation-error`, `@error-case`); `npm run traceability` fails on a test without them, or with two layers. `api-tests/docs/test-scenarios.md` opens with the grid, one row per operation with its documented statuses and the scenario IDs per layer; a documented status is in a cell or in "Left out" with a reason. Three layers, as at Hublo: the state rules (409 `INVALID_STATE`, 400 `INVALID_TRANSITION`) are error cases, the completeness gate (422 `INCOMPLETE_OFFER`) and a `reject` without reason are validation errors. A scenario that mixed two layers in one test (reject, partial save) is two tests under the same ID. The tags sit on the `test()` call, where the check reads them, not on a `describe`.

Consequences: `npx playwright test --grep @error-case` runs a layer, `--grep @workflow` a feature, `--grep @smoke` the acceptance subset. A new operation is a row of the grid before it is a test: its documented statuses each land in a cell or in "Left out". A folder is a feature tag, so moving a file changes its tag and the check says so. A boundary comes in pairs, one on each side of the rule (`amount` -1 refused, 0 accepted), the refused side under `@validation-error`, the accepted one under `@happy-path`.
