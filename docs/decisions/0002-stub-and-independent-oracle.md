# 0002 A reference stub, and an oracle independent of it

Context: Part 1 ships an OpenAPI document and no server; the brief asks for a runnable collection.

Decision: `api-tests/stub/` implements the spec's rules on `node:http` and zod; Playwright starts it as `webServer` on `TEST_ENV=local`, and `TEST_ENV` or `API_BASE_URL` points the same suite at a deployment. Expected values come from `src/oracle.ts`, written from the spec by hand: the status chain of each of the 8 flag combinations and the invalid pairs. Imports between `src/` or `tests/` and `stub/` are refused by eslint and the pre-write hook. The stub is three folders, `http/` the adapter, `domain/` the rules and request shapes, `store/` the memory; `domain/` depends on nothing, enforced the same way.

Consequences: green on a clean clone, every assertion meaningful, a wrong rule in the stub turns a test red. A new state enters in a few named places and nowhere else. Say TO_REVIEW, between TO_APPROVE and TO_POST behind a `reviewRequired` flag: one chain in the oracle (`HAPPY_PATHS` with the flag on, the status in `WITHDRAWABLE`), one branch in `stub/domain/state-machine.ts` and the flag in its schemas, one row in the scenario table. Also the status in `src/enum/job-offer.enum.ts` (`JOB_OFFER_STATUSES`) and the flag in the spec, then `npm run gen:types`. OFR-002 and OFR-003 derive their rows from that status list, so the edit and delete guards of the new state appear without a new test; WFL-002 reads the hand-written `INVALID_TRANSITIONS`, so its new pairs are typed in; and the grid of `docs/test-scenarios.md` shows the cells still empty: its happy path with the flag on, its 400 on a wrong action. A mock replaying examples would have left transitions and tenancy untestable.
