# 0008 User-facing locators, CSS only where the app gives no handle

Context: the Conduit frontend carries no `data-testid`, no `id`, no `aria-*` and no `<label>` (upstream source, `frontend/src`); its fields have placeholders, its buttons and links their text, its titles are headings. A test id means patching the system under test, which the brief hands over as is. The first selectors were CSS chains of Bootstrap classes (`.article-page .article-meta a.nav-link:has-text(...)`): they broke on a markup change no user sees, and passed while the visible name changed.

Decision: a selectors file holds locator factories, `(page) => Locator`, in Playwright's order: `getByRole` with the accessible name, then `getByPlaceholder`, then `getByText`. CSS stays one class, never a chain, and only where the app gives no handle: a container with no role, scoped then filtered by what it shows (the `.banner` that holds the author, the `.article-content` of the body, a comment `.card` by its text, `.error-messages`, `.article-preview` while the list loads); the user-menu toggle, a `div` with a click handler and no name without the username. A name shared by two elements is told apart by the user's view too: the author's avatar is a link named after them with no text, so the author link is the one with text; Follow and Unfollow differ by one case-sensitive word; the delete button of a comment is an icon with no name, the only button of its card. A hash route keeps the previous screen until the next one renders, its headings included: a page object that opens a screen waits for something only that screen shows (the profile's name, the editor's prefill) before a page-wide locator asserts. A page object never builds nor narrows a locator. eslint holds both rules.

Consequences: a locator fails when what the user reads changes, not when a class does, and its failure names the role and text it looked for. Each CSS left is a finding for the app, an `aria-label` on the icon buttons and a `<label>` per field; a test id added there replaces exactly those, in the selectors file only.
